# Отчёт 11 — как связать Godot с репозиторием и что значит «подключить меня к Godot»

**Дата:** 17 ноября 2026
**Статус:** инструкция. Я не проверял её в живом Godot — движок в моём окружении не запускается, поэтому проверка за Вами.

## 1. Прямой ответ: «подключить меня к Godot» технически нельзя

Меня нельзя подключить к программе на Вашем компьютере. Я работаю в отдельном
удалённом окружении: у меня есть только этот репозиторий и сеть. Доступа к Вашему
ноутбуку, к папкам, к редактору Godot и к экрану у меня нет и не будет.

Поэтому связка устроена иначе:

```
Вы (Godot на ноутбуке) → файлы проекта → GitHub → я читаю и правлю
                ↑                                    ↓
                └──────── git pull / коммит ─────────┘
```

Я правлю код в репозитории, Вы забираете изменения к себе. Это надёжнее прямого
доступа: ничего не ломается без Вашего ведома, и вся история правок видна.

## 2. Как связать Godot с GitHub

**Важно: сам Godot не умеет отправлять файлы на GitHub.** В нём нет git. Связку
делают двумя способами — выбирайте по удобству.

### Способ А: GitHub Desktop (проще всего, рекомендую)

1. Установите [GitHub Desktop](https://desktop.github.com) и войдите в свой аккаунт.
2. `File → Clone repository` → выберите `IAmStarhead/Project-Gene` →
   путь, например `C:\Dev\Project-Gene`.
3. Ветку выберите `arena/3b0477a7-project-gene` — там вся текущая работа.
4. Открывайте проект в Godot именно из этой папки.
5. Когда что-то изменили в Godot — в GitHub Desktop появятся изменённые файлы,
   внизу слева пишете описание и нажимаете **Commit to arena/…**, затем **Push origin**.

Дальше цикл простой: я пушу → Вы нажимаете **Fetch origin / Pull** → у Вас свежие файлы.

Плюс: GitHub Desktop **покажет конфликты**, если мы оба изменим один файл.

### Способ Б: плагин Git для Godot

В Godot есть встроенная панель Git, но она работает только если в системе установлен
git и включён плагин. В 4.x это делается через `AssetLib` или установкой аддона
`git` вручную, затем `Project → Version Control`. Панель минимальна: коммит и push,
без удобного просмотра изменений. Для начала я бы её не трогал.

### Чего делать НЕ надо

- **Не ставьте «синхронизацию папки» с автоотправкой** (типа Dropbox для рабочей папки
  проекта). Godot создаёт много служебных файлов, они начнут конфликтовать.
- **Не отправляйте** `.godot/` — это кэш импорта. Он попадает в `.gitignore` (см. ниже).
- **Не храните в репозитории большие видео и архивы.** Git их запоминает навсегда,
  и репозиторий распухает. Для видео — ссылка или временное хранение.

## 3. Что нужно добавить в `.gitignore` для Godot

Когда появится проект Godot, в корне нужен такой блок (я добавлю сам, когда создам
проект, но полезно знать):

```
# Godot
.godot/
*.translation
export.cfg
export_presets.cfg
.import/
```

## 4. Порядок работы, который предлагаю

1. **Вы** клонируете репозиторий через GitHub Desktop в отдельную папку.
2. **Я** создаю в репозитории папку `prototype/` с проектом Godot: комната, капсула,
   управление, настройки в одном файле.
3. **Вы** нажимаете Pull, открываете проект в Godot, запускаете F5.
4. **Вы** присылаете скриншот или ошибку из панели «Вывод».
5. **Я** правлю, пушу, и цикл повторяется.

Разделение простое: **я пишу код, Вы запускаете и говорите, что чувствуете.** Ошибки
и скриншоты — мой «глаз», слова о ощущениях — самое ценное, что я не могу получить сам.

## 5. Если что-то пойдёт не так

| Симптом | Что делать |
| --- | --- |
| GitHub Desktop пишет про конфликт | Ничего не выбирать самому, прислать мне список конфликтующих файлов |
| Godot не видит изменения после Pull | `Project → Reload Current Project` |
| Проект не открывается после моих правок | Прислать текст ошибки из «Вывод»; я откачу коммит |
| Файл модели «сломался» | Модель в репозитории не перезаписывается: её можно вернуть из истории |
