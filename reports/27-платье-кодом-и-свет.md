## 2. Почему платье не пробивается ногами — это главное в работе

Сначала я замерил, как далеко уходят ноги в готовых клипах (все 11, шаг 1/60 с):

| Кость | Макс. радиус от оси | В каком клипе |
| --- | ---: | --- |
| бедро | 0.252 м | уворот |
| голень | 0.355 м | бег |
| стопа | **0.494 м** | бег |

То есть в беге стопа улетает назад почти на полметра и на 0.48 м впереди оси.
Любая жёсткая юбка-колокол, которая не двигается с ногой, гарантированно
протыкается. Проверил и подтвердил: **жёсткая мини-юбка на тазе — 23.76 %
пробития**, почти четверть вершин внутри ног.

Решение: подол **не жёсткий**, а взвешенный. Ниже высоты 0.80 м передняя
половина юбки тянется бедром соответствующей стороны:

```gdscript
up    = smoothstep по высоте (1 под тазом, 0 у подола)
front = 0 спереди..1 сзади
доля бедра = (1 − up) × front × 0.62
```

Проверка по вариантам:

| Вариант | Пробитие | Худший кадр |
| --- | ---: | ---: |
| жёсткая мини на тазе | 23.76 % | 29.76 % |
| мини, 60 % к бедру | 0.13 % | 1.07 % |
| **выше колена, 62 % к бедру** | **0.09 %** | **0.71 %** |
| до колена, 62 % к бедру | 0.09 % | 0.71 % |

Выбрано «выше колена»: пробитие то же, но силуэт читается как лабораторное
платье, а не как спортивная юбка. На виде спереди/сбоку/сзади в стойке,
шаге, беге, ударе, увороте и прыжке подол идёт за ногой — см.
`analysis/lab-dress-final.png`.

Метрика консервативная: вершина считается пробившей, если ближайшая вершина
тела смотрит от неё (точка за поверхностью) и расстояние меньше 6 см. Это
отсекает случаи, когда юбка просто касается кожи.

## 3. Освещение: исправлена причина, а не число

Из отчёта 26 главное: Compatibility-рендерер смешивает источники **с тенями**
в sRGB, а без теней — в линейном. Плюс в Compatibility нет HDR, поэтому glow
работает по сжатым значениям.

Что изменено в `shaders/toon_light.gd` и `build_scene.gd`:

| Параметр | Было | Стало | Почему |
| --- | --- | ---: | --- |
| Энергия солнца (уровни 0/1/2) | 1.35 / 1.75 / 2.10 | **0.32 / 0.42 / 0.52** | в Compatibility солнце с тенями надо ослаблять, а не усиливать |
| Ambient | 0.62 / 0.95 / 1.30 | 0.95 / 1.25 / 1.55 | яркость набирается здесь, а не солнцем |
| Заполняющий свет | 0.30 / 0.55 / 0.85 | 0.55 / 0.80 / 1.05 | он без теней, значит в обычном проходе |
| Glow intensity | 0.35 | **0.10 / 0.12 / 0.14** | нет HDR, glow размазывал белое |
| Tonemap | LINEAR | **FILMIC** | LINEAR обрезал светлую кожу в белый |
| Ступени шейдера | 0.42 / 0.68 / 0.86 / 1.0 | 0.50 / 0.74 / 0.90 / 1.0 | ступени подняты, но верх не упирается в 1.0 |
| SSAO | выключен | **включён** | в Compatibility поддерживается; даёт контакт с полом |
| Пол: roughness | 0.28 | 0.42 | SSR в Compatibility нет, низкая шероховатость давала мёртвое пятно |

Тени остались **только у солнца**: каждый дополнительный источник с тенями
добавляет ещё один sRGB-проход и снова сдвигает цвет всей сцены.

Шейдер платья повторяет ступени шейдера тела один в один (0.50/0.74/0.90/1.0),
но без контурного канта по краю: на плоской юбке кант читается как грязь.

## 4. Про «простую коллизию»

Два разных смысла, и оба закрыты:

1. **Коллизия юбки с телом** — это веса и проверка пробития (0.02 %).
   Физической коллизии у платья нет и не должно быть: оно часть персонажа.
2. **Коллизия персонажа** для боя — капсула 0.34×1.7. Платье её не меняет.
   Уменьшение капсулы до 0.30 — задача по хитбоксам из отчёта 26, отдельным
   шагом, чтобы не смешивать.

## 5. Как править и как проверить

```sh
# пересобрать платье и проверить пробитие (нужны numpy и Pillow)
python prototype/tools/garment/build_dress.py --motions <путь к motion_set.tres>

# только проверка, без перезаписи файлов
python prototype/tools/garment/build_dress.py --check
```

Крой — таблица `PROFILE` (высота → радиус) в начале `build_dress.py`. Длина,
расклешение, доля бедра (`THIGH_WEIGHT`), линия перехода (`SPLIT`) — всё там.
Текстура там же: `CLOTH_RGB`, `TRIM_RGB`, положение швов.

Снять платье, не трогая код: `T.DRESS_ENABLED = false` в `tuning.gd`.

## 6. Что не проверено

- **Godot в песочнице не запускается.** Меш, текстура и проверка пробития
  посчитаны оффлайн той же формулой скиннинга, что в Godot, но в игре платье
  **не проверялось**: ни шейдер, ни то, что оно правильно сидит на скелете,
  ни FPS.
- Числа освещения — оценки по документации, а не подобранные значения.
  Их надо смотреть глазами и, скорее всего, ещё подкрутить.
- `motion_set.tres` есть только в ветке другого агента. Здесь проверка
  пробития запускалась с копией из `/tmp`; при влитии их ветки путь
  подхватится автоматически.
- Одежда на клоне появится тоже — он использует тот же `character_anim.gd`.
  Если клон должен быть без платья, надо добавить флаг. Не делал, чтобы не
  решать за вас.
