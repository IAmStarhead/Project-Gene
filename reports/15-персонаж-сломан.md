# 15. Почему персонаж «сам дерётся» и складывается пополам

Дата: 17 ноября 2026. Разбор двух дефектов, найденных по скриншоту первого
запуска с моделью.

## Что было на экране

Модель героини видна, текстура кожи применилась, но:

| Наблюдение пользователя | Что это на самом деле |
| --- | --- |
| «ужас, что это» | скелет сложился: руки вывернуты вверх, между ними тянутся растянутые полосы меша |
| «сама дерётся» | удар запускался каждый кадр без нажатия кнопки |
| «как будто сама ходит» | на экране «состояние: атака: замах» — анимация удара дёргала корпус |
| «стамина: 0» | каждый самозапуск удара тратил 18 стамины, восстановиться она не успевала |

Вторая и третья жалобы — **одна причина**. Четвёртая — её следствие.

## Дефект 1: удар без нажатия кнопки

В `player.gd` буфер ввода хранил «сколько секунд назад нажата кнопка».
Начальное значение было `-99.0` — условное «очень давно».

Условие запуска удара:

```
if _buf_attack <= T.INPUT_BUFFER and _spend_stamina(T.ATTACK_STAMINA):
```

`INPUT_BUFFER` равно 0.16. Проверка `-99.0 <= 0.16` **истинна**. То есть
на первом же кадре игра считала, что игрок только что нажал ЛКМ, хотя кнопку
никто не трогал. Удар запускался, тратил стамину, заканчивался — и запускался
снова, потому что после завершения буфер снова сбрасывался в `-99.0`.

Исправление: «не нажимали» теперь `999.0` (константа `BUF_NEVER`), и проверка
стала корректной.

Заодно добавлена строка отладки в оверлей:

```
действие: 0.12  буфер: удар нет / уворот нет
```

Если там появится число при ненажатой кнопке — значит причина вернулась.

## Дефект 2: скелет складывается

Это ошибка понимания, а не опечатка. В Godot **поза кости — абсолютная**:
это полный поворот кости относительно родителя, а не добавка к позе покоя.

Документация `Skeleton3D`: «The overall transform of a bone with respect to
the skeleton is determined by bone pose. **Bone rest defines the initial
transform of the bone pose**».

Первая версия кода делала так:

```
skeleton.set_bone_pose_rotation(i, bend)        # НЕВЕРНО
```

Кость получала только изгиб и теряла наклон, который был у неё в покое.
У плеча в покое ось направлена вниз, у предплечья есть наклон — всё это
пропадало. Кости выстраивались в линию, руки уходили вверх, меш растягивался
полосами между костями.

Правильно:

```
skeleton.set_bone_pose_rotation(i, rest_rotation * bend)   # ВЕРНО
```

То же для положения таза: `rest_position + offset`, а не просто `offset`.

## Как проверены знаки углов

После исправления формулы остаётся второй вопрос: **в какую сторону** гнётся
колено и машет рука. Ошибка знака даёт вывернутые назад колени — тоже
«ужас», только другой.

Проверено расчётом, без Godot: написана точная копия формулы на Python,
читающая скелет прямо из GLB. Считаются мировые позиции костей.

Сначала проверка показала ошибку 1.8 метра на позе покоя — но виноват был
**сам проверочный скрипт**: у узлов без поворота он подставлял `[0,0,0,1]`
вместо `[1,0,0,0]`, то есть «поворот на 180°» вместо «без поворота».
После исправления поза покоя совпала с эталоном **с точностью 0.0000 м**
по всем семи проверенным костям.

Результаты по знакам:

| Кость | Ось | Плюс | Минус |
| --- | --- | --- | --- |
| бедро | X | нога вперёд | нога назад |
| голень | X | переразгибание (запрещено) | колено сгибается назад — верно |
| предплечье | X | локоть сгибается, кисть вперёд | рука разгибается назад |
| плечо | X | мах вперёд | мах назад |
| плечо | Z | левая рука в сторону, правая к телу | наоборот |

Проверка позы бега по фазам шага (9 положений цикла):

- кисти всё время на высоте 0.86–0.88 м, голова на 1.46 м — **руки нигде
  не поднимаются выше головы**;
- носки не опускаются ниже 0.017 м (в покое 0.020) — **в пол не проваливаются**;
- стопы расходятся вперёд-назад в пределах ±0.5 м — шаг читается.

## Что осталось непроверенным

- **Godot не запускался.** Все числа выше получены расчётом по данным модели,
  а не наблюдением. Расчёт совпадает с тем, что делает Godot, только если
  `set_bone_pose_rotation` трактует позу как абсолютный поворот относительно
  родителя — на это указывает документация, но проверка в песочнице невозможна.
- **Порядок умножения.** В коде `rest * bend`, то есть изгиб применяется
  в осях покоя кости. Это соответствует смыслу «повернуть кость вокруг её
  собственной оси». Проверить вживую нельзя.
- **Как это выглядит.** Механику можно посчитать, вид — нет. Оценка остаётся
  за пользователем.

## Если снова что-то не так

Что прислать, чтобы правка была точной:

1. Скриншот в **покое** (не двигаться, не бить).
2. Скриншот **в шаге**.
3. Строку `действие / буфер` из оверлея — если при ненажатой кнопке там число,
   причина в вводе, а не в анимации.

Знаки правятся в одном месте: `_walk()` и `_attack()` в
`prototype/scripts/character_anim.gd`. Знак любого угла — это один символ.
